# Project Guide

## Purpose

This project populates the **Device Addressing** section of CloudVision's
**Management Connectivity Studio** from a CSV file. The main script is
`manage_static_mgmt_ip.py`.

The script:

1. Reads and validates device management addressing from CSV.
2. Looks up each device hostname in CloudVision inventory.
3. Uses the returned device serial number in the studio resolver query.
4. Opens a CloudVision workspace and updates Device Addressing.
5. Builds the workspace and optionally submits and approves its change control.

## Dependency and runtime

- Python 3.12+
- `cloudvision>=1.29.1`
- An authentication token with access to inventory, studios, workspaces, and
  change controls

Install the SDK with:

```bash
pip install 'cloudvision>=1.29.1'
```

## Input CSV

The required header is:

```text
device,mgmtVRF,enabled,ipv4Address,defaultGateway,additionalInterfaces
```

- `device` is a CloudVision hostname. It is resolved to a serial number using
  the inventory API.
- `mgmtVRF` must match a Management Connectivity Studio VRF option.
- `enabled` accepts common true/false values and becomes `Yes` or `No`.
- `ipv4Address` is required and must be a valid IPv4 address with CIDR
  notation, such as `192.0.2.10/24`.
- `defaultGateway` is required and must be a plain IPv4 address, such as
  `192.0.2.1`.
- `additionalInterfaces` can be empty, comma-separated interface names, or a
  JSON list of objects containing `interfaceName` and optionally
  `ipv4Address`.

Invalid input stops the script before a workspace is created.

## CloudVision data shape

The studio root uses the `deviceAddressing` resolver collection. Each CSV row
becomes a resolver entry with this structure:

```json
{
  "inputs": {
    "deviceAddressing": {
      "managementInterface": {
        "ipConfiguration": {
          "ipv4Configuration": {
            "ipv4Address": {
              "ipv4Address": "192.0.2.10/24"
            }
          }
        },
        "enabled": "Yes"
      },
      "managementVrf": "MGMT",
      "defaultGateway": {
        "ipv4Gateways": [
          {"ipv4Address": "192.0.2.1"}
        ]
      },
      "otherInterfaces": []
    }
  },
  "tags": {"query": "device:<serial-number>"}
}
```

The script reads the existing studio root first and replaces only
`deviceAddressing`, preserving other Management Connectivity settings.

## Command modes

`--mode` is required:

- `discover` prints the live studio schema and current root input without
  creating a workspace.
- `workspace-only` builds a workspace and leaves it open for review.
- `submit-workspace` submits the workspace and leaves its change control open.
- `submit-all` submits the workspace and approves the resulting change
  control. It does not start change-control execution.

Example:

```bash
python3 manage_static_mgmt_ip.py \
  --server cloudvision.example.com \
  --token-file service-account.tok \
  --input-file devices.csv \
  --mode workspace-only \
  --workspace-name "Static IP Assignment"
```

Use `--insecure` for environments with certificates that cannot be validated.
Use `--debug` to print each validated CSV row and retry information while
suppressing noisy third-party protocol logging.

## Development checks

Run these checks after Python changes:

```bash
python3 -m py_compile manage_static_mgmt_ip.py
git diff --check
```

Do not commit authentication tokens, generated bytecode, or workspace data.
